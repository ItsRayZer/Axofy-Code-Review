Possible SQL injection — query built by string concatenation

The query is built by concatenating userId, which comes straight from req.query.id, into the SQL string. An attacker can inject SQL through the id parameter.

Evidence:

const query = "SELECT * FROM users WHERE id = " + userId + " AND active = 1";

```suggestion
Use a parameterised query / prepared statement with placeholders instead of string concatenation.
```

Insecure eval() on untrusted input

eval() runs the caller's term string as code. Any input that reaches this function executes with the server's privileges.

Evidence:

const filter = eval("(" + term + ")");

Suggested fix (one-click, GitHub suggestion block):

```suggestion
Do not use eval(). Parse data with JSON.parse or a safe expression parser, and validate the input first.
```

How it works — the same method, step by step

The review is a pipeline, not a single call. Most of the work goes into preparing the context before any model writes a comment.

  1. 1. WebhookInstall the GitHub App. A PR opened or updated fires a webhook — no CI changes, no Docker, no API key needed for the hosted path.
  2. 2. QueueJobs are deduplicated by repo, PR, and head SHA, debounced 30 seconds, and superseded pushes are cancelled — rapid pushes collapse into one review.
  3. 3. SandboxAn ephemeral worker clones the repo (sparse checkout honouring your path filters). Untrusted repo code is never executed.
  4. 4. Code graphA fresh per-review graph of definitions, call sites, and imports — never a stale index — traces the blast radius of every changed function.
  5. 5. ReviewA planner turns the PR into a task graph. The review works through the diff, the code graph, linked issues, CI logs, and your guidelines — then 20+ deterministic tools run in parallel.
  6. 6. JudgeA separate judge pass scores every finding against the gathered context and drops ungrounded ones. What survives is what gets posted.
  7. 7. PostSummary into the PR description, inline comments anchored to exact diff lines with suggestion blocks, and a check run your branch protection can gate on.

Method note: the pipeline shape above follows CodeRabbit's public docs and the independent teardown of its pipeline (June 2026). Internal details such as instance sizes and model names in that teardown are reported, not vendor-confirmed.

Install the GitHub App

Two minutes. No CI changes, no Docker.

  1. Create the appGitHub → Settings → Developer settings → GitHub Apps → New GitHub App. Name it Axofy Code Review, homepage URL your server URL, webhook URL https://<your-server>/webhook/github, webhook secret = your GITHUB_WEBHOOK_SECRET.
  2. Set permissionsRead-only: Actions, Checks, Discussions, Members, Metadata. Read-write: Code, Commit statuses, Issues, Pull requests. No write access to repo contents — it never pushes, branches, or merges.
  3. Subscribe to eventspull_request, pull_request_review_comment, issue_comment, check_run.
  4. Install + configureInstall on your repos. Set GITHUB_APP_ID + GITHUB_APP_PRIVATE_KEY in .env and restart. Without the app, reviews still run from this page — posting is skipped with a clear note.

Questions

Is it really free?

Yes. There is no paid tier, no seat billing, and no billing code in the app at all. The models run on free tiers and the app runs on free hosting tiers. The tradeoff is rate limits on those free tiers, not a paywall.

How does free work, technically?

Reviews call NVIDIA's free Nemotron endpoint first, with Groq, OpenRouter free models, and Gemini AI Studio as fallbacks. You can also bring your own free key. The app stretches the free tier with 7-day response caching, per-file caching, a 30-second push debounce, incremental-only reviews, and cheap-model compression before the review pass.

Does it work on private repos?

Yes, with a GitHub token and a model key in .env. Public repos work without any token. Private repo code is only sent to the model provider you configured, and the review cache is local with a 7-day TTL.

What data is stored?

Reviews, learnings, and knowledge-base entries are stored locally in JSON files in the MVP (Postgres/pgvector is phase 2). Set knowledge_base.opt_out: true to disable retention features and delete the stored data. Nothing is used to train models.

How is this different from CodeRabbit?

Same method and same result format — webhook, queue, sandbox, code graph, review, judge, posted summary and inline comments. Different in price (free, everything included), model choice (you see and choose the model), and hosting (self-host is the default, no seat minimum). Axofy Code Review is independent and not affiliated with CodeRabbit.

What is not built yet?

The IDE extension, the Engineer cloud agent, SSO / RBAC / audit logs, and Postgres-backed learnings. GitLab, Bitbucket and Azure DevOps are adapter-ready (webhook parsing + docs) but not live — they need their host token configured. The CLI, GitHub App, and all review features above are built.
